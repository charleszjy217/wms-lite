# 生产切换 Checklist

> 最后更新: 2026-07-04  
> 用途: 从沙箱/测试环境切换到生产环境前逐项人工确认  
> 标注: ⚠️ = 需人工确认

---

## 如何使用

1. 在切换前 **至少 48 小时** 开始逐一确认
2. 每完成一项在方括号中打勾 `[x]`
3. 如某项不适用，注明 N/A 并说明理由
4. 所有项确认完成后，方可执行切换
5. 切换完成后执行 [上线后验证](#5-上线后验证)

---

## 1. 基础设施准备

### 1.1 服务器与环境

- [ ]  **⚠️** 生产服务器的操作系统已加固（最小安装、关闭不必要的端口和服务）
- [ ]  **⚠️** Docker 和 Docker Compose 已安装且版本符合要求（Docker 24+, Compose 2.20+）
- [ ]  **⚠️** 服务器时间同步已配置（NTP/Chrony）
- [ ]  **⚠️** 防火墙规则已配置，仅开放必要端口（443, 80, 或自定义端口）
- [ ]  **⚠️** 反向代理（Nginx / Caddy / Traefik）已配置 TLS 证书（Let's Encrypt 或商业证书）
- [ ]  **⚠️** 反向代理的速率限制和 WAF 已启用
- [ ]  **⚠️** 服务器的监控告警工具已部署（Node Exporter / 云监控 Agent）

### 1.2 域名与 DNS

- [ ]  **⚠️** 生产域名（如 `wms.example.com`）已解析到生产服务器 IP
- [ ]  **⚠️** API 域名（如 `api.wms.example.com`）已配置 DNS 解析（如与前端分离）
- [ ]  **⚠️** SSL 证书已签发且在有效期内
- [ ]  **⚠️** A/AAAA 记录 TTL 已临时降低（便于回滚切换）

### 1.3 数据库

- [ ]  **⚠️** PostgreSQL 16+ 已安装并优化配置（shared_buffers, work_mem, max_connections 等）
- [ ]  **⚠️** 数据库连接使用 SSL（sslmode=require）
- [ ]  **⚠️** 数据库备份策略已配置（完整备份 + WAL 归档）
- [ ]  **⚠️** 数据库备份已成功执行至少一次并可恢复验证
- [ ]  **⚠️** 数据库用户权限最小化（仅应用所需的最小权限）
- [ ]  **⚠️** 数据库连接池（PgBouncer）已配置（如预期高并发）
- [ ]  **⚠️** 数据库迁移文件已在测试环境完整运行通过

## 2. 应用配置

### 2.1 环境变量与密钥

- [ ]  **⚠️** `NODE_ENV=production` 已设置（生产模式）
- [ ]  **⚠️** `JWT_SECRET` 已设置为高强度随机字符串（`openssl rand -hex 64`），**与沙箱环境不同**
- [ ]  **⚠️** `DATABASE_URL` 已指向生产数据库，含 SSL 参数
- [ ]  **⚠️** `POSTGRES_PASSWORD` 已设置为强密码，**与沙箱环境不同**
- [ ]  **⚠️** `CORS_ORIGIN` 已设置为生产前端域名（多个域名用逗号分隔）
- [ ]  **⚠️** `VITE_API_BASE_URL` 已设置为生产 API 地址（前端构建前确认）
- [ ]  **⚠️** `LOG_LEVEL=info` 或 `warn`（避免 debug 日志过多）
- [ ]  **⚠️** 所有集成层密钥（`INTEGRATION_ERP_API_KEY` 等）已配置为生产环境的密钥
- [ ]  **⚠️** 密钥管理方案（Vault / K8s Secrets / Docker Secrets）已就绪
- [ ]  **⚠️** `.env` 文件**没有**被提交到版本控制（检查 `git status`）
- [ ]  **⚠️** 所有环境变量已通过 `docker compose config` 验证无误

### 2.2 后端

- [ ]  **⚠️** 后端代码已通过所有单元测试和集成测试
- [ ]  **⚠️** Prisma 迁移已在生产数据库上试运行（`prisma migrate deploy`）
- [ ]  **⚠️** 种子数据检查：生产环境不执行 `prisma db seed`（或仅执行必要的初始化数据）
- [ ]  **⚠️** 已确认无调试端点或测试路由暴露
- [ ]  **⚠️** 请求体大小限制已配置
- [ ]  **⚠️** CORS 来源列表已确认无误

### 2.3 前端

- [ ]  **⚠️** 前端已使用生产 API 地址构建（`VITE_API_BASE_URL` 正确）
- [ ]  **⚠️** 前端构建产物经过测试，无运行时错误
- [ ]  **⚠️** 前端 Nginx 配置已优化（缓存、gzip、安全头）

### 2.4 Docker 配置

- [ ]  **⚠️** Dockerfile 无敏感信息泄露（密钥、证书等）
- [ ]  **⚠️** 镜像已构建并通过安全扫描（无高危漏洞）
- [ ]  **⚠️** `docker-compose.yml` 中 `restart: unless-stopped` 已设置
- [ ]  **⚠️** 日志轮转配置已添加（避免磁盘写满）
- [ ]  **⚠️** 资源限制（CPU/内存）已配置在 compose 文件中
- [ ]  **⚠️** 健康检查配置已验证

## 3. 集成端点配置

### 3.1 端点切换确认

- [ ]  **⚠️** 每个集成端点的 `environment` 已从 `SANDBOX` 改为 `PRODUCTION`
- [ ]  **⚠️** 每个端点的 `baseUrl` 已指向生产环境 URL
- [ ]  **⚠️** 每个端点的认证密钥已切换为生产密钥
- [ ]  **⚠️** 沙箱和生产环境的 API 端点均已通过连通性测试
- [ ]  **⚠️** 生产环境的接口返回数据格式已确认与沙箱一致
- [ ]  **⚠️** 每个端点的幂等键机制已启用并验证

### 3.2 主数据同步 (ERP → WMS)

- [ ]  **⚠️** 沙箱环境已测试：商品、分类、供应商同步均通过
- [ ]  **⚠️** 字段映射已确认（字段名、格式、枚举值映射表）
- [ ]  **⚠️** 增量同步逻辑已确认（`updatedSince` 参数正常）
- [ ]  **⚠️** 全量同步初始加载时间可接受（如有必要）
- [ ]  **⚠️** 重试策略：退避时间、最大重试次数合理

### 3.3 财务推送 (WMS → 财务系统)

- [ ]  **⚠️** 沙箱环境已测试：库存变动推送成功接收
- [ ]  **⚠️** 推送载荷格式已与财务方确认
- [ ]  **⚠️** 推送失败告警已配置
- [ ]  **⚠️** 死信队列机制已启用

### 3.4 SSO / 认证集成

- [ ]  **⚠️** SSO/OIDC 生产环境端点已配置
- [ ]  **⚠️** 回调 URL 已更新为生产域名
- [ ]  **⚠️** 沙箱测试用户登录流程通过
- [ ]  **⚠️** Token 验证和刷新流程正常

## 4. 安全与合规

### 4.1 安全检查

- [ ]  **⚠️** 安全 Checklist 中所有 ✅ 项已确认通过（参见 [安全清单](./security-checklist.md)）
- [ ]  **⚠️** 所有管理员默认密码已更改
- [ ]  **⚠️** 弱口令用户已在生产环境禁用或强制重置密码
- [ ]  **⚠️** HTTPS 已强制启用（HTTP 请求重定向到 HTTPS）
- [ ]  **⚠️** HTTP 安全头已配置（HSTS, X-Frame-Options, X-Content-Type-Options 等）
- [ ]  **⚠️** npm 依赖已审计（`npm audit --audit-level=high` 无高危漏洞）
- [ ]  **⚠️** Docker 镜像无已知 CVE（通过 Trivy / Snyk 扫描）

### 4.2 审计与日志

- [ ]  **⚠️** 审计日志写入已确认正常（所有模块的 CREATE/UPDATE/DELETE 操作）
- [ ]  **⚠️** 审计日志仅限 admin 角色查询
- [ ]  **⚠️** 日志持久化存储已配置（日志不丢失）
- [ ]  **⚠️** 日志不包含敏感信息（密码、Token 等）

### 4.3 备份与恢复

- [ ]  **⚠️** 数据库自动备份脚本已部署并测试
- [ ]  **⚠️** 备份文件存储在与生产环境隔离的存储位置
- [ ]  **⚠️** 恢复流程已文档化并测试至少一次
- [ ]  **⚠️** 回滚方案细则已确认（见 [回滚方案](#7-回滚方案)）

## 6. 部署执行

### 6.1 切换前准备

- [ ]  **⚠️** 切换窗口已确定并通知所有相关方（建议非业务高峰期）
- [ ]  **⚠️** 数据库已做完整备份（切换失败时可恢复）
- [ ]  **⚠️** 当前沙箱环境的配置快照已保存（用于回滚）
- [ ]  **⚠️** 回滚方案已打印或离线保存（应对网络故障）
- [ ]  **⚠️** 参与切换的工程师已确认分工

### 6.2 执行切换

- [ ]  **⚠️** 停止所有沙箱集成同步（暂停 cron / webhook handler）
- [ ]  **⚠️** 将 `.env.production` 部署到生产服务器
- [ ]  **⚠️** 执行 `docker compose up -d --build` 启动服务
- [ ]  **⚠️** 执行 `docker compose exec -T backend npx prisma migrate deploy` 运行数据库迁移
- [ ]  **⚠️** 验证后端健康检查通过
- [ ]  **⚠️** 验证前端可正常访问并加载数据
- [ ]  **⚠️** 验证用户登录正常（用户名密码 / SSO）
- [ ]  **⚠️** 启用生产环境集成端点（逐个启用，观察 5-10 分钟确认正常）

### 6.3 验证清单

- [ ]  **⚠️** `curl https://wms.example.com/api/v1/health` → `{"status":"ok"}`
- [ ]  **⚠️** 前端页面 `https://wms.example.com` 可正常加载
- [ ]  **⚠️** 管理员可登录并访问所有管理功能
- [ ]  **⚠️** 操作员可登录并执行出入库操作
- [ ]  **⚠️** 第一个集成同步任务 `COMPLETED` 成功
- [ ]  **⚠️** 数据库连接正常，数据读写无异常
- [ ]  **⚠️** 审计日志正常写入

## 7. 回滚方案

### 7.1 回滚触发条件

出现以下任一情况，**立即执行回滚**：

1. 健康检查失败超过 3 次
2. 用户登录大面积失败（超过 10% 的请求）
3. 核心业务 API（入库/出库/盘点）响应时间超过 10 秒
4. 数据库写入失败或数据损坏
5. 集成同步大面积失败（超过 50% 的端点）
6. 发现安全漏洞或数据泄露

### 7.2 回滚步骤

#### 方案 A：代码回滚（推荐）

```bash
# 1. 立即暂停集成同步
docker compose exec backend sh -c "curl -X POST http://localhost:3000/api/v1/integration/pause-all"

# 2. 切回上一个稳定版本
git checkout <上一个稳定版本的 commit 或 tag>
docker compose up -d --build

# 3. 回滚数据库（如有 schema 变更）
# 注意：Prisma 迁移回滚需手动操作，推荐使用 `prisma migrate resolve`
docker compose exec -T backend npx prisma migrate resolve --rolled-back "<迁移名称>"

# 4. 验证回滚后的服务正常
curl -sf http://localhost:3000/api/v1/health

# 5. 恢复集成同步（逐个恢复并验证）
# 切换回沙箱环境配置
```

#### 方案 B：数据库回滚

```bash
# 1. 停止所有服务
docker compose down

# 2. 恢复数据库备份
# 从备份文件恢复 PostgreSQL 数据库
pg_restore -U wms_user -d wms_lite -c /backup/wms-lite-pre-switch.dump

# 3. 启动上一个版本的代码
git checkout <上一个稳定版本>
docker compose up -d --build

# 4. 验证服务正常
curl -sf http://localhost:3000/api/v1/health
```

#### 方案 C：DNS 切换（多环境部署时）

```bash
# 1. 修改 DNS 记录，将生产域名指向旧环境 IP
# 2. 等待 DNS 缓存过期（建议 TTL 设为 60 秒）
# 3. 验证旧环境正常
# 4. 分析切换失败原因，修复后重新尝试
```

### 7.3 回滚后的操作

- [ ]  **⚠️** 通知所有相关方切换已回滚
- [ ]  **⚠️** 确认回滚后的服务运行正常
- [ ]  **⚠️** 保留切换失败的日志和分析数据
- [ ]  **⚠️** 启动切换失败原因调查（RCA）
- [ ]  **⚠️** 修复问题后在沙箱重新测试
- [ ]  **⚠️** 重新安排切换窗口

## 8. 上线后验证

### 8.1 24 小时观察期

- [ ]  **⚠️** 上线后前 30 分钟全程监控服务状态
- [ ]  **⚠️** 检查第一个完整业务周期（如批处理任务）正常执行
- [ ]  **⚠️** 检查所有集成端点至少一次完整同步
- [ ]  **⚠️** 检查日志无异常错误（ERROR 级别日志零增长）
- [ ]  **⚠️** 检查数据库连接池使用率在正常范围

### 8.2 确认最终状态

- [ ]  **⚠️** 沙箱环境仍可用且隔离（不影响生产）
- [ ]  **⚠️** 所有监控告警正常
- [ ]  **⚠️** 生产环境 DNS TTL 恢复为正常值（如之前已降低）
- [ ]  **⚠️** 切换记录已归档（时间、参与人、配置快照）

## 9. 切换任务时间线参考

| 时间 | 任务 |
|------|------|
| T-48h | 通知相关方，确认切换窗口 |
| T-24h | 运行完整的切换预演（沙箱环境） |
| T-4h | 生产数据库全量备份 |
| T-1h | 暂停所有沙箱集成同步 |
| T-0 | **开始切换**：部署代码，运行迁移 |
| T+15min | 验证后端+前端+数据库 |
| T+30min | 逐个启用集成端点 |
| T+1h | 验证第一个完整业务周期 |
| T+24h | 最终确认，切换完成 |
