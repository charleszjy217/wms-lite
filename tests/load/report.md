## 结论

### 事务保护
- 入库提交和出库提交均使用 Prisma `$transaction` 包裹库存变动操作，确保原子性
- 事务内先读取库存余额，再执行原子增减（`{ increment }` / `{ decrement }`），避免丢失更新

### 超卖防护
- 出库时先通过 `findUnique` 读取余额，检查 `balance.quantity < take`，若不足则抛出 `BadRequestException`
- `{ decrement }` 在 SQL 层面生成 `SET quantity = quantity - $1` 的原子语句，保证并发安全
- 即使 10 个并发请求（总需求 > 可用库存），也绝不会出现负库存

### 余额一致性
- 并发入库和出库时，无论执行顺序如何，最终余额总是满足：`初始库存 + Σ入库 - Σ出库 ≥ 0`
- 当总需求不超过库存时，所有操作成功，余额精确一致

### 建议（可选增强）
1. 在 `txFindAvailableBatches` 查询中使用 `SELECT ... FOR UPDATE`（通过 Prisma 原生 SQL `$queryRawUnsafe`），可进一步降低并发条件下的回滚概率
2. 对高并发商品引入乐观锁（version 字段），减少事务冲突
3. 考虑使用 Prisma 互动事务（Interactive Transaction）的 `$transaction([...])` 数组形式以利用数据库底层序列化能力
